# Test Strategy

## Layers
| Layer | Tooling | Location | Runs |
|---|---|---|---|
| Unit | pytest | `apps/api/tests/unit` | pricing, units, matching, parsers (pure functions), csv neutralisation, pdf determinism |
| Integration (API + PostgreSQL + RLS) | pytest + httpx TestClient + real PostgreSQL 16 | `apps/api/tests/integration` | auth, tenancy, catalog import, RFQ flow, quotes, approvals, exports, audit, concurrency |
| Security / negative | pytest `-m security` | `apps/api/tests/security` | tenant isolation, RBAC, CSRF, file abuse datasets, SQLi strings, logging redaction, LLM injection fixtures |
| Migration | alembic upgrade head on empty DB + downgrade one + upgrade | CI job | schema integrity |
| API contract | OpenAPI exported and diffed against `docs/openapi.json` | CI job | contract drift |
| Web static | `tsc --noEmit`, `eslint`, `next build` | `apps/web` | type/lint/build |
| E2E browser | Playwright (Chromium) | `tests/e2e` | S1-A20 full flow, permission states, XSS fixture, 409 banner |
| Scans | pip-audit, npm audit, bandit, ruff S-rules, gitleaks, semgrep (if available) | `make security-scan` | evidence under `docs/evidence/` |

## Independence
QA engineer derives cases from PRD acceptance IDs (S1-A01…A20) without reading implementation first; the implementer's
tests are a floor, not the gate. The security auditor owns `tests/security` datasets. The release reviewer reads evidence
only and cannot run or edit tests.

## Fixtures
Synthetic only: `apps/api/app/fixtures/` (demo orgs, catalog CSV), `tests/fixtures/` (RFQ pdf/xlsx/csv/text; malformed
and malicious samples generated by `scripts/make_fixtures.py` so binaries are reproducible).

## Exact commands
```bash
make db-up                       # local PostgreSQL + roles + databases
cd apps/api && uv run pytest -q                              # all api tests (unit + integration + security)
cd apps/api && uv run pytest -q -m "not integration"         # unit only (no DB)
cd apps/api && uv run pytest -q -m security                  # security suite
cd apps/api && uv run alembic upgrade head && uv run alembic downgrade -1 && uv run alembic upgrade head
cd apps/web && npx tsc --noEmit && npx eslint . && npm run build
make e2e                                                     # starts api (seeded) + web, runs Playwright
make security-scan
```
Evidence files: `docs/evidence/qa-stage1-<date>.md`, `docs/evidence/security-stage1-<date>.md`,
`docs/evidence/release-review-stage1-<date>.md` with command, exit code, counts.

## Coverage targets
Pricing/matching/units/parsers ≥ 90 % line coverage; overall API ≥ 80 % (reported, not gating in Stage 1).

## Later stages
Stage 2 adds provider simulator contract tests, job runner idempotency/backoff tests with fake clock, OAuth failure
injection. Stage 3 adds KPI golden fixtures, connector conflict suites, role-aware export tests. Stage 4 adds red-team
prompt-injection corpus, tool-policy property tests, budget/kill-switch tests, workflow dry-run side-effect assertions.
