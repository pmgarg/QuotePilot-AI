## Observations (not defects)
1. Event-triggered workflows run with the identity and role of the user whose action fired the event (e.g. the approver); approval of paused steps is then owner/admin only.
2. `GET /platform/plan` and `GET /platform/kill-switch` are readable by every role (billing reference masked for non-owners) — consistent with UI banners.
3. Plan downgrade is accepted even when current usage exceeds the new limits (members, connectors, active workflows); limits bite only on the next creation/activation.
4. A subscription with a non-active status pauses metered features (assistant); RFQ creation is also metered, so it is paused too (not asserted).
5. Stage 4 tool `export_customers` produces `tool.*` audit rows; REST export additionally writes `export.customers`.
